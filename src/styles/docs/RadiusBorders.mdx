# Radius & Borders

Corners are soft, and the map is by **surface type**, not by taste:

| surface | radius |
| --- | --- |
| card, section, modal panel, KPI tile | `--radius-lg` (14) |
| button, field, select, nav item, menu | `--radius-md` (10) |
| chip, badge, swatch, tag, inner cell | `--radius-sm` (6) |
| segmented pill, progress track, status dot, avatar | `--radius-full` |
| large surface / sheet | `--radius-xl` (20) |

An inner corner sitting flush inside an outer one is **derived**, never a second
literal: `calc(var(--radius-lg) - var(--border-1))`. SectionCard's band is the
worked example — it cannot clip with `overflow: hidden` (that eats the hint's
focus ring on all 13 cards), so it rounds its own top corners, and a literal
would leave a silent step the moment either scale moved.

Borders are hairlines, and they carry separation **before** a shadow does.
`--border-1` is the structural default everywhere; `--border-2` is reserved for
emphasis the hairline cannot carry — a selection ring, a dashed drop target, the
dotted/dashed projection states below. `--color-border` is the default hue,
`--color-border-subtle` the quietest split, `--color-border-strong` the one that
has to survive a busy surface.

## Shape carries projection state

real / estimated / simulated must be distinguishable without color: a solid
hairline is real, dotted is estimated, dashed cobalt is simulated. The label
always comes with it.
