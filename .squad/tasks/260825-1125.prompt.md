# Fazer o dashboard obedecer o Perfil e remover seus controles

## Outcome
R1. O dashboard não tem mais nenhum controle próprio: o seletor de alvos do Teto de Gastos
    (`25% / 50% / 75% / Meta`) e o seletor de dados simulados saíram da tela.
R2. `GET /api/dashboard` aceita **só** `?owner=`; o teto, o limite de objetivos e a
    contagem de simulações vêm da linha `Settings`, caindo em `DEFAULT_SETTINGS` quando
    nunca houve linha salva.
R3. Com o teto em **porcentagem**, cada mês libera essa fatia do pior saldo projetado
    daqui pra frente, descontado o que os meses anteriores já liberaram — exatamente os
    números de hoje para 25/50/75.
R4. Com o teto em **valor fixo**, cada mês libera o valor informado, mesmo quando isso
    deixa algum mês projetado no vermelho.
R5. O limite mensal de objetivos segue o ajuste do Perfil (porcentagem do teto médio do
    período ou valor fixo); em 25% em porcentagem o ritmo é idêntico ao de hoje.
R6. Quando um valor fixo salvo está acima do máximo atual, o dashboard mostra um alerta no
    topo com um link para `/perfil`; quando não está, não mostra nada.

## Design
- **Contract — `buildCeiling` troca o par `(cap, limit)` por um alvo.** Em
  `src/app/api/dashboard/ceiling.types.ts`:
  ```ts
  export type CeilingTarget =
    | { mode: "percent"; percent: number } // 0..100
    | { mode: "fixed"; cents: number };
  ```
  ```ts
  export function buildCeiling(
    points: MonthPoint[],
    currentMonth: number,
    target: CeilingTarget,
  ): Ceiling
  ```
  `percent` mantém o corpo de hoje (`offered = floor(gap * percent / 100)`, zerado quando há
  mês no vermelho). `fixed` faz `budget = cents` direto: **sem** `min` com o `gap` e **sem**
  o zeramento por mês vermelho. É essa diferença que produz R4 — `ceilingLeft` passa a poder
  ficar negativo, e é o sinal que R6 mostra.

- **Contract — `Ceiling` ganha um campo.** `fixed: boolean` — este teto veio de um valor
  fixo, não de uma fatia do saldo. Substitui o `byMeta` do card e é o que decide o rótulo do
  limite. `headroomCents` (do `260825-1123`) segue independente do alvo ativo: continua
  sendo o máximo que não deixa mês futuro no vermelho, em qualquer modo.

- **Contract — `savingPace` recebe o alvo de objetivos.** Mesma união, nome próprio para não
  confundir os dois ajustes:
  ```ts
  export type GoalsTarget = CeilingTarget;

  export function savingPace(ceiling: Ceiling, target: GoalsTarget): number
  ```
  `percent`: `floor(total * percent / (100 * ceiling.months.length))`, com `total` a soma dos
  `budget` — em `percent: 25` isso é o mesmo número que `floor(total / (4 * n))`, e é assim
  que R5 se prova sem reescrever expectativa nenhuma. `fixed`: devolve `cents` como está,
  sem clamp — deixar o ritmo irreal é o que R6 sinaliza em vez de esconder.

- **Contract — `DashboardData` ganha `overHeadroom: boolean`** e **perde `meta`**. Verdadeiro
  quando um valor fixo salvo passou do máximo atual:
  `(ceilingMode === "fixed" && ceilingCents > headroomCents) || (goalsMode === "fixed" &&
  goalsCents > headroomCents)`. Calculado no `service.ts`, que é o único lugar com a linha de
  `Settings` e o `Ceiling` na mão ao mesmo tempo. `meta` sai porque existia só para o
  `CapSelector` decidir se oferecia o segmento Meta.

- **Chose um boolean no payload over o dashboard buscar `/api/settings`** — a tela já faz um
  fetch só; um segundo fetch para descobrir se deve mostrar um aviso é uma condição de
  corrida a troco de nada. E `headroomCents` é a régua dos dois valores fixos, o que deixa a
  condição inteira num lugar.

- **Contract — o rename das entradas do route.** `GET /api/dashboard` passa a validar só
  `owner` (422 quando ausente, como hoje). `capSchema` e `simulationSchema` saem, e
  `getDashboard(owner: string)` fica com um argumento. Em `dashboard-inputs.helper.ts`,
  `metaOf`/`targetCap`/`limitFor` são removidos e entram dois leitores de `Settings`:
  ```ts
  export function ceilingTargetOf(settings: Settings): CeilingTarget
  export function goalsTargetOf(settings: Settings): GoalsTarget
  ```
  e `forecastsFor(showSimulated: boolean, all: Forecast[])` no lugar da versão por string,
  com a mesma posição no fluxo (antes do `derivePeriod`).

- **Contract — o que é deletado.** `src/lib/ceiling-caps.ts`, `src/lib/simulation.ts`,
  `DashboardScreen/simulation.hook.ts`, `DashboardScreen/components/SimulationSelect/`,
  `CeilingCard/components/CapSelector/`, e os `tests/` de cada um. `BoardProps` fica
  `{ data: BoardData }`. `CeilingCardProps` perde `cap`, `onCapChange` e `meta`.

- **Chose apagar `src/lib/simulation.ts` over guardar o par `SIMULATION_VIEWS`** — com
  `showSimulated` sendo boolean persistido, o vocabulário `"real" | "all"` não tem as duas
  pontas de fio que justificavam o arquivo. O comentário dele (*"the filter runs before
  derivePeriod"*) tem que sobreviver, migrado para `forecastsFor`.

- **Contract — o alerta.** Renderizado no `DashboardScreen/index.tsx` **acima** do `Board`,
  quando `data.status === "ok" && data.overHeadroom`, como um `Notice` com um `next/link`
  para `/perfil` no corpo. Não substitui o board: o board continua mostrando os números que
  o valor fixo produz, inclusive os meses negativos.

- **Chose alerta no dashboard over aviso na tela de Perfil** — o input do Perfil já trava no
  máximo no momento da edição (`260825-1124`); o estouro só nasce depois, quando uma previsão
  nova derruba o headroom. Quem vê o mês negativo é quem está olhando o dashboard.

- **Flow — a copy dos quatro pontos.** `SavingsSection/hook.ts` e `hints.ts` param de citar
  "25%" e de descrever seletores que não existem mais: passam a dizer que o número vem do
  Perfil, sem repetir o valor (repetir é o que já fez essa copy envelhecer duas vezes).
  `ForecastForm` passa a dizer que a exibição de simulações é um ajuste do Perfil.

## Forbidden
- Não deixe `cap` nem `simulation` como query param aceito "por compatibilidade": o app é
  local e não tem outro cliente.
- Não mova o `forecastsFor` para depois do `derivePeriod`.
- Não faça o modo `fixed` respeitar o `gap` nem o mês vermelho: o valor fixo é literal, e é
  disso que R4 e R6 dependem.
- Não faça clamp do valor fixo de objetivos no `savingPace`.
- Não toque em `ceiling-math.helper.ts` — ele não conhece alvo nenhum, e é isso que o
  mantém separado.
- Não acrescente nome novo a `MvIconName` nem componente novo a `src/components/`.
- Não deixe o dashboard fazer um segundo fetch (`/api/settings`) para decidir o alerta.
- Não repita o número do ajuste na copy (o "25%" de hoje é a terceira vez que essa copy
  envelhece junto com uma constante).
- Nenhuma cor, espaço, raio, sombra ou duração hardcoded nos `.scss` tocados.
