# Cobrir src com testes unitarios Jest a 90 por cento

## Context desta tarefa

Depende de **260812-1106**, que já está mergeado quando esta roda. Pode assumir que
existem: `jest.config.ts` com `next/jest` e `testMatch:
["<rootDir>/src/**/tests/*.test.{ts,tsx}"]`, `jest.setup.ts` com
`@testing-library/jest-dom`, os scripts `test` / `test:coverage` / `typecheck`,
`biome.json` com `linter.rules.preset: "all"`, `e2e/` e Playwright removidos,
`.squad/ARCHITECTURE.md` já reescrito com a convenção do arquivo irmão, e dois testes
de exemplo: `src/lib/tests/money.test.ts` e
`src/components/MoneyInput/tests/hook.test.ts`.

## Outcome
R1. Todo arquivo `.ts`/`.tsx` sob `src/` que emite código executável tem o irmão
    `<dir>/tests/<nome>.test.<ext>`, e nenhum arquivo de teste vive fora de um `tests/`.
R2. `npm run test:coverage` sai com código 0 tendo `coverageThreshold.global` em **90**
    para `statements`, `branches`, `functions` e `lines`, medido sobre todo `src/`
    exceto `src/generated/**` e `src/**/tests/**`.
R3. Nenhum teste toca disco de banco: rodar a suíte com `dev.db` ausente passa igual, e
    `dev.db` não é criado nem alterado pela suíte.
R4. `npm run lint` e `npm run typecheck` continuam saindo 0 com os arquivos de teste na
    árvore — inclusive o cap de 100 linhas plano em cada `*.test.ts(x)`.

## Context

- **Tamanho real da superfície.** Não confie neste número, meça no início:
  ```
  find src -type f \( -name '*.ts' -o -name '*.tsx' \) | grep -v '^src/generated/' | wc -l
  ```
  Na investigação deu **259**, distribuídos assim:
  `src/lib/**` 11 · `src/core/**` 13 (12 só-tipo + `core/use-cases/period.service.ts`) ·
  `src/infra/**` 7 · `route.ts` 10 · `service.ts` 10 · `*.helper.ts` 28 ·
  `hook.ts` + `*.hook.ts` 84 · `index.tsx` 81 · `types.ts`/`*.types.ts` 4 ·
  `page.tsx`/`layout.tsx` 7 · avulsos 4 (`nav.ts`, `hints.ts`, `chart.config.ts`,
  `src/styles/fonts.ts`). Zero `.js`/`.jsx` no projeto.

- **Cuidado — o seam de mock é o repositório, não o Prisma.**
  `src/infra/db/client.ts` instancia `PrismaClient` com
  `process.env.DATABASE_URL ?? "file:./dev.db"` **em escopo de módulo**: importar um
  `service.ts` sem mock abre o banco do dono. Os services importam o singleton
  concreto, sem injeção:
  ```ts
  // src/app/api/people/service.ts
  import { personRepository } from "@/infra/repositories/person.prisma.repository";
  export function listPeople() { return personRepository.list(); }
  ```
  Mocke `@/infra/repositories/*.prisma.repository`. `src/app/api/dashboard/service.ts`
  puxa **quatro** repositórios.

- **Cuidado — os `instanceof` de erro Prisma nas rotas.** Cinco `route.ts`
  (`people`, `goals`, `movements`, `forecasts`, `ofx-imports`) fazem
  `import { Prisma } from "@/generated/prisma/client"` e ramificam em
  `error instanceof Prisma.PrismaClientKnownRequestError` com `error.code` `P2002`,
  `P2025`, `P2003`. Um erro mockado como objeto literal **não** satisfaz o `instanceof`
  e o teste cai silenciosamente no ramo `throw`/500 — o branch pretendido fica
  descoberto e o teste passa medindo outra coisa. Construa o erro real a partir de
  `@/generated/prisma/client`.

- **Imitar** — a forma de `route.ts`, que é onde mora o branching e portanto a
  cobertura de `branches`:
  ```ts
  export async function PUT(request: NextRequest) {
    const parsed = updateSchema.safeParse(await safeJson(request));
    if (!parsed.success) { return fail("Dados inválidos", "validation", 422); }
    try { return ok(await updatePerson(parsed.data)); }
    catch (error) {
      if (error instanceof Prisma.PrismaClientKnownRequestError) {
        if (error.code === "P2002") return fail("Já existe uma pessoa com esse nome", "duplicate", 409);
        if (error.code === "P2025") return fail("Pessoa não encontrada", "not_found", 404);
      }
      return fail("Erro ao atualizar pessoa", "internal", 500);
    }
  }
  ```
  Cada `route.ts` precisa de um caso por ramo: sucesso, 422 de validação, e cada código
  Prisma mapeado. `src/lib/http.ts` importa `NextResponse` de `next/server` em runtime,
  então toda suíte de rota carrega o Next.

- **Imitar** — a separação `index.tsx` / `hook.ts`. Por convenção do
  `.squad/ARCHITECTURE.md`, o `index.tsx` "blindly calls the folder's `hook.ts` and
  renders its return — no logic, state or effects". O menor deles,
  `src/components/Button/index.tsx`, tem 5 linhas:
  `return <button {...useButton(props)} />;`. Consequência prática: **a lógica está nos
  84 hooks e a asserção de valor está lá**; os 81 `index.tsx` precisam de um render que
  os cubra, não de asserção de comportamento.

- **Reuse** — hooks se testam com `renderHook` de `@testing-library/react` (já
  instalado pela 260812-1106). Exemplo de hook com efeito de DOM real, em
  `src/components/MoneyInput/hook.ts`: `useLayoutEffect` + `input.setSelectionRange`,
  já coberto pelo teste de exemplo daquela tarefa — use-o como molde.

- **Reuse** — relógio injetado. `src/lib/months.ts` expõe
  `currentYYYYMM(now = new Date())` e `greeting.helper.ts` recebe `date: Date` por
  parâmetro. **Não** use `jest.useFakeTimers()` onde a data entra por parâmetro.

- **Cuidado — `src/lib/decode.ts`** usa `new TextDecoder(..., { fatal: true })`. O
  polyfill do `jest-environment-jsdom` não é o do Node; esse arquivo pede o docblock
  `@jest-environment node`.

- **Cuidado — hooks com estado de plataforma**: `ThemeToggle/hook.ts` e
  `ProfileProvider/hook.ts` mexem em `localStorage`/`document`;
  `src/components/AppShell/nav.hook.ts` e
  `src/components/AppShell/components/Aside/hook.ts` chamam `usePathname` de
  `next/navigation` — precisa de `jest.mock("next/navigation")`.

- **Cuidado — o cap de 100 linhas plano vale para cada arquivo de teste**
  (`scripts/check-line-cap.sh` varre `src`). Uma suíte de `route.ts` com 6 ramos não
  cabe em um arquivo; o `testMatch` é `tests/*.test.{ts,tsx}`, então
  `tests/route-post.test.ts` e `tests/route-put.test.ts` são nomes válidos.

- **Cuidado — `preset: "all"` do Biome vale para os testes.** `style/noMagicNumbers`
  dispara em toda asserção com literal numérico (`expect(formatCents(123))`), e
  `domains.test: "all"` liga as regras de teste do Biome. Ver `## Design`.

## Design

- **Contract — `coverageThreshold`** em `jest.config.ts`:
  ```ts
  coverageThreshold: { global: { statements: 90, branches: 90, functions: 90, lines: 90 } }
  ```
  `collectCoverageFrom` fica como a 260812-1106 deixou:
  `["src/**/*.{ts,tsx}", "!src/generated/**", "!src/**/tests/**"]`. Nada mais entra na
  lista de exclusão — a barra é global sobre `src/`, decisão do dono.

- **Contract — quem ganha arquivo irmão.** Todo arquivo que emite código executável.
  Ficam **sem** teste os que compilam para módulo vazio e não têm o que cobrir:
  `src/core/entities/*.entity.ts` (6), `src/core/repositories/*.repository.ts` (6) e os
  4 `types.ts`/`*.types.ts`. Eles seguem dentro do `collectCoverageFrom` e reportam sem
  statements, sem distorcer o denominador.
- **Chose não escrever teste de tipo puro** — um `expect(true).toBe(true)` ao lado de um
  `type` não pode falhar, e 16 deles diluem a revisão do que importa. Quem valida esses
  arquivos é `npm run typecheck`.

- **Contract — ambiente por camada.** `jsdom` é o default do `jest.config.ts`. Levam o
  docblock `/** @jest-environment node */` na primeira linha os testes de: `src/lib/**`,
  `src/core/use-cases/**`, `src/infra/**`, e todos os `route.ts`/`service.ts`/
  `*.helper.ts` sob `src/app/api/**`.
- **Chose docblock por arquivo em vez de `projects`** — a 260812-1106 já fixou essa
  decisão; mantê-la evita duas configs de cobertura somando denominadores diferentes.

- **Contract — estratégia de mock, uma por camada, sem exceção:**
  - `src/lib/**`, `*.helper.ts` puros, `core/use-cases/period.service.ts`: **sem mock**,
    entrada e saída direto.
  - `service.ts`: `jest.mock("@/infra/repositories/<entidade>.prisma.repository")`,
    asserta que o repositório foi chamado com o argumento certo e que o retorno passa
    adiante.
  - `route.ts`: mocka o `./service` irmão. Requisição montada com
    `new Request(url, { method, body })`, resposta lida com `await res.json()` e
    `res.status`. Para os ramos Prisma, o rejeitado é um
    `Prisma.PrismaClientKnownRequestError` de verdade, importado de
    `@/generated/prisma/client`.
  - `infra/repositories/*.prisma.repository.ts`: `jest.mock("@/infra/db/client")`
    devolvendo um objeto com os métodos Prisma usados como `jest.fn()`.
  - `hook.ts`: `renderHook` + `act`. Nada de renderizar o componente pai para exercitar
    o hook.
  - `index.tsx`: `render()` de `@testing-library/react` com props mínimas e asserção no
    que está na tela (texto, `role`, atributo) — nunca snapshot.
- **Chose asserção de tela em vez de snapshot nos 81 `index.tsx`** — snapshot cobre a
  linha e não detecta regressão nenhuma que importe; e um snapshot desatualizado vira
  `-u` reflexo.

- **Contract — `overrides` de teste no `biome.json`**, acrescentado por esta tarefa:
  ```json
  { "includes": ["src/**/tests/**"],
    "linter": { "rules": { "style": { "noMagicNumbers": "off" } } } }
  ```
- **Chose desligar `noMagicNumbers` só dentro de `src/**/tests/**`** — em teste o
  literal numérico **é** a asserção (`expect(addMonths(202612, 1)).toBe(202701)`);
  extraí-lo para constante nomeada torna o teste ilegível e some com o valor esperado.
  Nenhuma outra regra do `preset: "all"` é afrouxada nos testes: o cap de 100 linhas
  continua valendo e força suíte dividida em vez de arquivo gigante.

- **Chose cobrir por comportamento observável, não por linha** — a meta é 90%, mas o
  critério de aceite de cada teste é asserção sobre valor de retorno ou sobre tela.
  Teste que só importa o módulo para "tocar" a linha é o que esta tarefa proíbe.

## Steps
1. Ligar `coverageThreshold.global` em 90 e acrescentar o `overrides` de
   `noMagicNumbers` para `src/**/tests/**`. A suíte fica vermelha aqui — é o gate
   nascendo, não uma regressão. → R2
2. `src/lib/**` (11) e `src/core/use-cases/period.service.ts`: teste irmão para cada,
   ambiente `node`, sem mock. `money.test.ts` já existe — estender se faltar ramo. → R1
3. Os 28 `*.helper.ts`, com prioridade para os 7 de
   `src/app/api/dashboard/` (`ceiling-math`, `ceiling`, `goals`, `pace`, `payload`,
   `series`, `stats`) e os 4 de `src/app/api/ofx/` (`ofx-tags`, `parse`, `period`,
   `report`) — é onde mora a regra de negócio do teto e do OFX. → R1
4. Camada API: 10 `service.ts` mockando o repositório, 10 `route.ts` mockando o service,
   um caso por ramo de status. → R1 R3
5. Os 7 `infra/repositories/*.prisma.repository.ts` mais `infra/db/client.ts`, com
   `@/infra/db/client` mockado. → R1 R3
6. Os 84 hooks com `renderHook`, começando por `src/components/**` e seguindo para
   `src/app/**/_components/**`. → R1
7. Os 81 `index.tsx`, as 7 páginas/layout e os 4 avulsos (`nav.ts`, `hints.ts`,
   `chart.config.ts`, `src/styles/fonts.ts`). → R1
8. Fechar o gap até `npm run test:coverage` sair 0, medindo o que falta com
   `npx jest --coverage --coverageReporters=text` e atacando os arquivos de menor
   cobertura primeiro. → R2 R4

## Verify
- R1: `find src -type f \( -name '*.ts' -o -name '*.tsx' \) ! -path 'src/generated/*' ! -path '*/tests/*'`
  contra `find src -path '*/tests/*' -name '*.test.*'` — a única diferença aceitável são
  os 16 arquivos só-tipo nomeados em `## Design`. E
  `find src -name '*.test.*' ! -path '*/tests/*'` retorna vazio.
- R2: `npm run test:coverage` — sai 0. A tabela final mostra `All files` com os quatro
  percentuais em 90 ou acima.
- R3: `mv dev.db dev.db.bak 2>/dev/null; npm run test; test ! -f dev.db; mv dev.db.bak dev.db 2>/dev/null`
  — a suíte passa e nenhum `dev.db` é criado.
- R4: `npm run lint` sai 0 (inclui `biome check .` e o cap de 100 linhas em cada teste
  novo) e `npm run typecheck` sai 0.

## Scope
- In: arquivos novos `src/**/tests/*.test.{ts,tsx}` · `jest.config.ts` (só
  `coverageThreshold`) · `biome.json` (só o `overrides` de `src/**/tests/**`).
- Out: `.github/` (é a 260812-1108) · o código de produção sob `src/`, que não muda —
  ver `## Forbidden` · `prisma/` · `src/generated/` · `.squad/ARCHITECTURE.md`, já
  reescrito pela 260812-1106.

## Forbidden
- Mudar código de produção para facilitar teste. Se um arquivo for realmente
  intestável sem refatoração, pare e reporte — não refatore por conta própria, e não
  contorne com teste que não asserta.
- `jest.mock("@/infra/db/client")` fora das suítes de `infra/repositories/**`. Nas
  outras camadas o seam é o repositório.
- Objeto literal fazendo as vezes de `Prisma.PrismaClientKnownRequestError`.
- Snapshot (`toMatchSnapshot`, `toMatchInlineSnapshot`) em qualquer teste.
- `it.skip`, `describe.skip`, `it.todo`, `xit` ou teste sem `expect`.
- Baixar o `coverageThreshold` abaixo de 90 ou acrescentar caminho ao
  `coveragePathIgnorePatterns` / à lista de exclusão do `collectCoverageFrom` para
  fechar a conta.
- Afrouxar qualquer regra do Biome além do `noMagicNumbers` em `src/**/tests/**`.
- Reintroduzir Playwright ou qualquer runner e2e.
