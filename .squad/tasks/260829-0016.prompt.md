# Recompor a dashboard em cards

## Outcome
R1. Em qualquer estado da tela o h1 **Dashboard** e o lede continuam visíveis, sem
    faixa invertida: sem full-bleed, sem fundo `--color-text`, sem `.edge`, sem `.glow`.
    Com payload `ok`, o saldo projetado (claim «Saldo projetado em …», `MoneyDisplay`
    `variant="hero"`, Delta vs saldo atual) vive num `Card` `variant="elevated"`
    `padding="lg"`. Esse card não contém Entradas / Saídas / Meses no vermelho. O
    bloco do título leva `.waiting` sem payload ou com `refreshing`; some com payload
    `ok` e sem refresh.
R2. Com payload `ok`, abaixo de `xl` o board é uma coluna na ordem DOM: saldo
    projetado → No período → Evolução mensal → Saldo acumulado → Teto de gastos →
    Capacidade de poupança. Em `xl`+ o mesmo DOM vira grid de duas colunas
    `minmax(0, 7fr) minmax(0, 5fr)` com áreas `hero | facts`, `bars | teto`,
    `line | teto`, `goals` na largura total. `PeriodFacts` tem 3 colunas de `md` até
    abaixo de `xl` e 1 coluna no rail (`xl`+). O teto empilha summary e tabela em
    qualquer largura — o split viewport `380px + 1fr` em `xl` não roda.
R3. A 375px o board não transborda na horizontal. Depois do grid, a `.plot` medida
    em `xl` mostra 12 meses e a de 375px mostra 6; `DESKTOP_PLOT_WIDTH` é o valor
    entre as duas medidas, não 768 copiado.

## Design
- **Contract — árvore**
  ```
  DashboardScreen
    HeroBand          // só h1 + lede + caret; data/refreshing só para `live`
    Notice*           // inalterado
    [aria-busy board] // só status ok
      Board           // seis filhos diretos, nesta ordem
        .hero   → ProjectedBalance   // Card elevated lg; figures
        .facts  → PeriodFacts
        .bars   → ChartCard Evolução mensal
        .line   → ChartCard Saldo acumulado
        .teto   → CeilingCard
        .goals  → SavingsSection
  ```
  Pasta nova sob `Board/components/ProjectedBalance/` (três arquivos). Pasta
  `HeroBand` permanece (nome estável). `useHeroBand` devolve `{ live }` — sem
  `figures`.

- **Contract — CSS do Board**
  ```scss
  .board {
    display: flex;
    flex-direction: column;
    gap: var(--space-8);
    @include t.bp("xl") {
      display: grid;
      grid-template-columns: minmax(0, 7fr) minmax(0, 5fr);
      grid-template-areas:
        "hero facts"
        "bars teto"
        "line teto"
        "goals goals";
    }
  }
  .hero, .facts, .bars, .line, .teto, .goals { min-width: 0; }
  @include t.bp("xl") {
    .hero  { grid-area: hero; }
    .facts { grid-area: facts; }
    .bars  { grid-area: bars; }
    .line  { grid-area: line; }
    .teto  { grid-area: teto; }
    .goals { grid-area: goals; }
  }
  ```
  Célula = `div` com a classe de área envolvendo o card (não vazar classes do
  Board para `Card` / `SectionCard`).

- **Contract — PeriodFacts**
  ```scss
  .facts {
    grid-template-columns: minmax(0, 1fr);
    @include t.bp("md") { grid-template-columns: repeat(3, minmax(0, 1fr)); }
    @include t.bp("xl") { grid-template-columns: minmax(0, 1fr); }
  }
  ```

- **Contract — teto** `.split` deixa de ramificar em `xl`. Uma coluna
  (summary, depois tabela) em qualquer breakpoint. Sem track `380px`.

- **Contract — plot** Com o grid no ar, medir `getBoundingClientRect().width` da
  `.plot` a 375px e a 1280px (rail expandido, 264px). `DESKTOP_PLOT_WIDTH` fica
  estritamente entre as duas. Testes de `chart.config` usam esses números.
  `Overview`/`Board` que mockam 884×240 podem manter 884 se 884 ≥ o novo limiar.

- **Flow** `HeroBand` fora do `aria-busy`: o caret dobra enquanto o board escurece.
  `ProjectedBalance` só existe com `status === "ok"` (dentro do Board). Loading /
  erro / `no_range` / `out_of_range`: título + Notice, sem card de saldo e sem
  board — como hoje sem figures.

- **Chose card contido over faixa invertida** — default do pedido; o glow cobalto
  fica no token (Storybook / README), sem consumidor na dashboard.
- **Chose grid `xl` 7/5 over só gap** — default do pedido; `xl` e não `lg` para o
  rail do teto não nascer em 1024.
- **Chose seis wrappers no Board over `className` nos primitivos** — `Card` /
  `SectionCard` / `ChartCard` não ganham API de layout.
- **Chose não tocar AppShell / tokens / `Card` scss** — blast radius é só `/`.
- **Chose não portar cartão, Add widget, lista de transações, lima** — não há
  produto equivalente; cobalto continua a única marca.

  PeriodFacts, CeilingCard `_split`, `chart.config.ts` + testes irmãos,
  `ProjectedBalance` novo), `DESIGN.md` só o parágrafo Hero Band.

## Forbidden
- Não inventar widget, controle no board, rota ou campo de API.
- Não usar lima / `--cat-lime` como marca; sem cor, raio ou espaço hardcoded.
- Não alterar `Card` / `SectionCard` / `AppShell` / tokens globais.
- Sem `grid-template-columns: 1fr` nu; sem split 380px do teto em `xl`.
- Sem faixa invertida nova e sem recolocar `--glow-brand` no hero.
- `src/generated/prisma/` e `prisma/migrations/` intocados.
- Cap 100 em todo arquivo tocado sob `src` (inclui testes e `.scss`). Sem barrel.
