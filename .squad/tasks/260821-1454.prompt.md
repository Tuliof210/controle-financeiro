# Filtrar e ordenar movimentações e previsões

## Outcome

R1. Dadas `/movimentacoes` e `/previsoes`, entre o título da página e as seções Entradas/Saídas aparece o mesmo controle: campo **Nome**, **Ordenar por** (Data inicial / Data de criação / Nome) e **Direção** (Crescente / Decrescente). Só `/previsoes` mostra **Classificação** (Todas / Fixa / Compromisso futuro).
R2. Dado um texto em Nome, as duas seções mostram só linhas cujo `name` contém o texto (trim, sem distinguir maiúsculas/acento); em previsões, Classificação ≠ Todas restringe por `kind`. Totais das seções batem com as linhas visíveis. O perfil do header continua filtrando antes. Simulado não é filtro.
R3. Ordenar por data inicial, data de criação ou nome, crescente ou decrescente, reordena **dentro** de cada seção. Sem interação, a ordem é a de hoje: data de criação crescente.

## Context

Filtro/ordem entram **depois** de `visibleFor` e **antes** de `splitByType`. `useEntryScreen` tem 100 linhas: extrair o estado da query para um filho (`list.hook.ts`); não crescer este arquivo.


## Design

- **Contract — query + adapters** em `src/lib/entry-list-query.ts`:

```ts
export const ENTRY_SORT_KEYS = ["initialDate", "createdAt", "name"] as const;
export type EntrySortKey = (typeof ENTRY_SORT_KEYS)[number];
export type EntrySortDir = "asc" | "desc";

export interface EntryListQuery {
  name: string;
  kind: "all" | string;
  sort: EntrySortKey;
  dir: EntrySortDir;
}

export const DEFAULT_ENTRY_LIST_QUERY: EntryListQuery = {
  name: "",
  kind: "all",
  sort: "createdAt",
  dir: "asc",
};

export interface EntryListAdapters<T> {
  getInitialDate: (item: T) => number;
  getCreatedAt: (item: T) => string | Date;
  getKind?: (item: T) => string;
}

export function applyEntryListQuery<T extends { name: string }>(
  items: T[],
  query: EntryListQuery,
  adapters: EntryListAdapters<T>,
): T[];
```

Nome: `trim`, `localeCompare`/`includes` com `sensitivity: "base"` e `"pt-BR"`; string vazia = não filtra. Kind: `query.kind === "all"` ou `getKind` ausente = não filtra; senão igualdade com `getKind(item)`. Sort estável. Data inicial: número YYYYMM. Nome: `localeCompare(..., "pt-BR", { sensitivity: "base" })`. Direção inverte o comparador.

- **Contract — `EntryListControls`** em `src/components/EntryListControls/` (três arquivos). Controlado:

```ts
export interface EntryListControlsProps {
  query: EntryListQuery;
  onChange: (query: EntryListQuery) => void;
  kinds?: { value: string; label: string }[];
}
```

Copy: **Nome** (placeholder "Buscar por nome"); **Classificação** só se `kinds` (Todas + as options); **Ordenar por** (Data inicial, Data de criação, Nome); **Direção** (Crescente, Decrescente). Sem `kinds`, o select de Classificação não existe e `query.kind` permanece `"all"`.

- **Contract — `EntryScreenConfig.list`:**

```ts
list: EntryListAdapters<T> & {
  kinds?: { value: string; label: string }[];
};
```

Obrigatório. Movimentações: `getInitialDate: (m) => m.month`, `getCreatedAt: (m) => m.createdAt`. Previsões: `getInitialDate: (f) => f.months[0] ?? 0`, `getCreatedAt: (f) => f.createdAt`, `getKind: (f) => f.kind`, `kinds` a partir de `FORECAST_KINDS` + `KIND_LABELS`. Toolbar entre `PageHeader` e `Sections`. Pipeline: `visibleFor` → `applyEntryListQuery` → `splitByType`. Estado da query: `useState(DEFAULT_ENTRY_LIST_QUERY)` no filho extraído; não sobrevive a desmontar a tela.

- **Flow** — client-side no array já carregado (GET continua sem query params).
- **Chose adapters over alargar `Entry`** — o mesmo motivo de `renderBadges`: campos assimétricos.
- **Chose não filtrar por tipo** — Entradas/Saídas já separam; um terceiro controle esvaziaria uma seção.
- **Chose `kind: "all" | string` over `ForecastKind`** — o controle não importa previsão.
- **Chose SelectField+TextField over KindToggle/popover** — precisa de "Todas" e de labels visíveis nas duas telas.
- **Chose client-side over GET `?sort=`** — o perfil já filtra no cliente; listar não tem params.
- **Chose não persistir URL** — o perfil já usa `localStorage`; filtro de lista é da visita.

## Steps

1. `entry-list-query.ts` + testes: nome (trim, case/acento, vazio), kind (igualdade, `"all"`, `getKind` ausente ignora), sort nas três chaves × duas direções, default `createdAt`/`asc`. → R2 R3

- Query params no GET, persistência em URL/`localStorage`.
- Filtro de tipo (Entrada/Saída) ou de `simulated`.
- Colocar `kind` / `createdAt` / `month` em `Entry`.
- Segundo controle de pessoa. Mexer em `renderBadges` / `ForecastBadges`.
- Playwright. Editar `src/generated/prisma/` ou migrations.
