# Fechar o ciclo do import OFX

## Outcome

R1. Antes de confirmar o import, o diálogo mostra em prosa visível (não só tooltip) que a ação não tem desfazer: as movimentações entram no banco e o mesmo arquivo não volta atrás.
R2. Após import bem-sucedido (`POST /api/ofx-imports` 2xx com criação), a UI navega para `/` — o dashboard, não o relatório com o botão Importar desabilitado.
R3. O botão Importar continua desabilitado + tooltip quando o hash já estava importado *antes* deste submit; nesse caso não há navegação extra.
R4. A cópia do aviso usa o mesmo grau de gravidade de `Excluir {nome}? Esta ação não pode ser desfeita.` em Pessoas — o import irreversível não é mais mais educado que apagar pessoa.

## Context

Depende de `260823-2122` para o header do leitor já falar em corrigir a projeção. Depende de `260823-2120` para `/` ter o teto como primeira cifra — o redirect pousa na mesada corrigida.

- **Imitate** `src/app/leitor-ofx/_components/OfxScreen/components/ReportView/components/ImportAction/hook.ts` — `submit` hoje: POST; se `already_imported` fecha o diálogo e marca `imported`; se sucesso, fecha, `setRecord({ imported: true, importedAt })`, **sem** `router.push`.
- **Imitate** `ImportAction/index.tsx` — modal “Importar extrato”, campos identificador + responsável, `view.summary` com “N movimentações serão criadas.”, footer Cancelar / submit. Sem frase de irreversibilidade. Sucesso = botão da página `disabled` + tooltip `"Este extrato já foi importado."`
- **Reuse** `ConfirmDialog` copy em `src/app/configuracoes/_components/SettingsScreen/components/PeopleSection/index.tsx`: `message={\`Excluir ${target?.name}? Esta ação não pode ser desfeita.\`}`.
- **Watch out for** o schema: `OfxImport` não aponta para as movimentações; **não há undo** — PRODUCT.md e `schema.prisma` já dizem isso. Não inventar desfazer. `already_imported` no meio do submit (corrida) já trata como fim: aí também não redirecionar (R3), só o 2xx que *criou* neste clique. `useRouter` de `next/navigation` no client component. Não tocar no hash SHA-256 nem em `createMany`.

## Design

- **Contract** — no corpo do modal, um parágrafo persistente (visível com o diálogo aberto), pt-BR, no sentido: importar grava as movimentações; não dá para desfazer; o mesmo arquivo não importa de novo. Não é `title` do modal.

Após `result.data` de sucesso (criação): `router.push("/")`. Não mostrar o estado “Importar disabled” como tela de sucesso.

- **Flow** — falha de rede / 422: diálogo aberto, `view.error`, sem navigate. `already_imported`: diálogo fecha, tooltip, permanece no relatório. Sucesso: navigate imediato; o relatório não precisa persistir o estado de vitória.
- **Chose** redirect para `/` **over** toast no relatório — o trabalho do import é corrigir o teto; o teto mora no dashboard.
- **Chose** aviso no diálogo **over** só no tooltip do botão disabled — o disabled aparece *depois*; a prevenção tem de ser *antes* do commit.

## Steps

1. Parágrafo de irreversibilidade no modal; alinhar gravidade à exclusão de pessoa. → R1 R4
2. `router.push("/")` só no sucesso que criou movimentações; `already_imported` fica no relatório. → R2 R3
3. Testes de `ImportAction` (hook + index) para aviso, navigate e o caso já-importado. → R1 R2 R3 R4

## Scope

- In: `ImportAction` (index, hook, copy helper, testes); eventualmente um `useRouter` mock nos testes.
- Out: `NAV`, decoder, `POST /api/ofx-imports` (contrato, hash, createMany), `HeroBand`, cap, `PeriodFacts`, desfazer de verdade.

## Forbidden

- Não adicionar DELETE de import / rollback de movimentações.
- Não redirecionar em erro.
- Não mudar o envelope `{ data } | { error }`.
- Teto de 100 linhas. Sem dependência nova.
