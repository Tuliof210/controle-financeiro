# Endurecer o Biome e trocar o Playwright por Jest

## Outcome
R1. `biome.json` roda com `linter.rules.preset: "all"` e `npm run lint` sai com código 0
    em toda a árvore — nenhuma regra desligada individualmente, nenhum
    `// biome-ignore` novo, nenhum `--max-diagnostics`.
R2. A regra `style/noExcessiveLinesPerFile` só é aplicada a `**/*.{js,jsx,ts,tsx}`;
    nenhum outro tipo de arquivo (`.json`, `.css`, `.md`, …) é reprovado por ela.
R3. Playwright saiu do projeto: `e2e/`, `playwright.config.ts`, `@playwright/test` e
    `e2e.db` não existem mais, e `npm test` não invoca Playwright.
R4. Jest roda no repo: `npm run test` e `npm run test:coverage` executam a suíte
    `src/**/tests/*.test.{ts,tsx}` e emitem relatório de cobertura. Sem
    `coverageThreshold` ainda — a barra de 90% é da tarefa 260812-1107.
R5. `npm run typecheck` existe e sai 0 (`tsc --noEmit`).
R6. `.squad/ARCHITECTURE.md` descreve o novo regime: Jest como único runner, a
    convenção de arquivo irmão, os comandos reais. Nenhuma linha do arquivo ainda
    afirma que e2e é o único runner ou que nada é testado em isolamento.

## Design

- **Contract — `biome.json`**: `linter.rules.preset: "all"`, mantidos
  `noExcessiveLinesPerFunction` e `noExcessiveLinesPerFile` com `maxLines: 100`, e:
  ```json
  "linter": {
    "domains": {
      "next": "all", "react": "all", "types": "all", "test": "all",
      "solid": "none", "qwik": "none", "vue": "none", "svelte": "none",
      "reactNative": "none", "drizzle": "none", "tailwind": "none", "turborepo": "none",
      "playwright": "none"
    }
  }
  ```
- **Chose declarar `domains` em vez de desligar regras** — `preset: "all"` liga o
  domínio Qwik (`useQwikValidLexicalScope`, 95 erros) e o Solid
  (`noSolidDestructuredProps`, `useSolidForComponent`, `noReactSpecificProps` — este
  último proíbe `className`/`onChange`). São regras de frameworks que este projeto não
  usa e que contradizem o React. `domains` é o campo que existe exatamente para dizer
  qual é a stack, e o `biome.json` já o usa. Isso **não** é uma deny-list de regras:
  toda regra que se aplica a Next+React+TS continua ligada e tem de passar.

- **Contract — escopo do `noExcessiveLinesPerFile`** via `overrides`, porque o campo
  `linter.rules` é global:
  ```json
  "overrides": [
    {
      "includes": ["**/*.js", "**/*.jsx", "**/*.ts", "**/*.tsx"],
      "linter": { "rules": { "style": { "noExcessiveLinesPerFile": { "level": "on", "options": { "maxLines": 100 } } } } }
    },
    {
      "includes": ["**"],
      "linter": { "rules": { "style": { "noExcessiveLinesPerFile": "off" } } }
    }
  ]
  ```
  A ordem importa: em Biome os `overrides` posteriores vencem, então descubra a ordem
  correta empiricamente (`npx biome check <um .json grande>`) e deixe a que de fato
  entrega R2. Se um único `override` com `includes` negativo
  (`["**", "!**/*.{js,jsx,ts,tsx}"]`) resolver, prefira ele — é uma regra em vez de duas.

- **Contract — a única exceção de regra, e por que ela não é opcional**:
  `style/noDefaultExport` é insatisfazível nos arquivos em que o framework *exige*
  `export default`. Desligue-a por `overrides` restrito a exatamente esses caminhos,
  com comentário de uma linha:
  `src/app/**/page.tsx`, `src/app/**/layout.tsx`, `next.config.ts`, `prisma.config.ts`,
  `jest.config.ts`, `.storybook/*.ts`. Fora dessa lista a regra vale.
  Se `useComponentExportOnlyModules` também for insatisfazível em `page.tsx`/`layout.tsx`,
  vale o mesmo tratamento e a mesma restrição de escopo. **Nenhuma outra regra ganha
  exceção** — se alguma parecer impossível, pare e reporte em vez de desligar.

- **Contract — `jest.config.ts`** na raiz:
  ```ts
  export default createJestConfig({
    testEnvironment: "jsdom",
    setupFilesAfterEach: undefined,               // usar setupFilesAfterEnv
    setupFilesAfterEnv: ["<rootDir>/jest.setup.ts"],
    testMatch: ["<rootDir>/src/**/tests/*.test.{ts,tsx}"],
    collectCoverageFrom: [
      "src/**/*.{ts,tsx}",
      "!src/generated/**",
      "!src/**/tests/**",
    ],
  });
  ```
  Sem `coverageThreshold` nesta tarefa. `jest.setup.ts` importa
  `@testing-library/jest-dom` e nada mais.
- **Chose `jsdom` como ambiente padrão** com docblock `@jest-environment node` por
  arquivo onde o teste for de `lib`/API — em vez de `projects` com dois ambientes.
  Um arquivo de config a menos e o override é local ao teste que precisa dele.

- **Contract — scripts do `package.json`** (substituem `test` e `test:e2e`):
  ```json
  "test": "jest",
  "test:coverage": "jest --coverage",
  "typecheck": "tsc --noEmit"
  ```
  `lint`, `lint:lines`, `lint:fix`, `format`, `db:*`, `dev`, `build`, `start`,
  `storybook`, `build-storybook` ficam como estão.

- **Contract — convenção de arquivo de teste**, a ser escrita em
  `.squad/ARCHITECTURE.md` e obedecida a partir da 260812-1107: para
  `<dir>/<nome>.<ext>` o teste é `<dir>/tests/<nome>.test.<ext>`, mesma extensão base
  (`.ts` para `.ts`, `.tsx` para `.tsx`). Um `tests/` por diretório que tenha código.

- **Chose remover o Playwright inteiro** em vez de manter uma suíte e2e reduzida — o
  dono determinou que e2e sai e a cobertura passa a vir de teste unitário. Manter as
  duas seria dois runners e dois gates para a mesma pergunta.

## Steps
1. Trocar `biome.json` para `preset: "all"` com os `domains` declarados, medir o
   estrago (`npx biome check . --reporter=summary`) e registrar o número no corpo do
   commit. → R1
2. Aplicar os `overrides`: escopo de `noExcessiveLinesPerFile` para js/jsx/ts/tsx e a
   exceção mínima de `noDefaultExport` nos arquivos que o framework obriga. → R1 R2
3. Remover Playwright: apagar `e2e/` e `playwright.config.ts`, desinstalar
   `@playwright/test`, tirar `e2e` dos três `git diff`/`git ls-files` de
   `scripts/check-line-cap.sh`, limpar `/test-results/` e `/playwright-report/` do
   `.gitignore`. → R3
4. Instalar e configurar o Jest: `jest`, `jest-environment-jsdom`, `@types/jest`,
   `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`;
   criar `jest.config.ts` e `jest.setup.ts`; trocar os scripts `test`/`test:e2e` por
   `test`/`test:coverage` e acrescentar `typecheck`. → R4 R5
5. Provar o harness com um teste real e mínimo: `src/lib/tests/money.test.ts` cobrindo
   `formatCents`, `formatMoney`, `formatMoneyShort`, `formatMoneyShortK`,
   `digitsToCents` (incluindo o clamp em `MAX_CENTS`), e
   `src/components/MoneyInput/tests/hook.test.ts` via `renderHook`. Dois arquivos, nada
   além disso — a bateria completa é a 260812-1107. → R4
6. Corrigir o código-fonte até `npm run lint` sair 0, começando por
   `useImportExtensions` (`allowImportingTsExtensions` no `tsconfig.json` + extensão nos
   imports relativos) e seguindo pelas frentes listadas em `## Context`. Quebrar em
   commits por frente de regra, não um commit único. → R1
7. Reescrever a seção **Testing** e as linhas de **Commands** de
   `.squad/ARCHITECTURE.md`: Jest como único runner, a convenção `tests/*.test.*`, os
   comandos `test`/`test:coverage`/`typecheck`, e a remoção do
   `npx playwright install chromium` do onboarding. Atualizar também a nota sobre
   `noExcessiveLinesPerFile` para refletir o novo escopo. → R6

## Verify
- R1: `npm run lint` — sai 0. E `npx biome check . --reporter=summary` não lista
  nenhuma regra. Confira com `git grep -n "biome-ignore"` que nenhuma supressão nova
  entrou, e com `git diff main -- biome.json` que os únicos `"off"` são os de

  — os três verdadeiros. `npm run lint:lines` sai 0.
- R4: `npm run test` — os dois arquivos passam. `npm run test:coverage` — imprime a

- R5: `npm run typecheck` — sai 0.
- R6: `grep -n "Playwright\|playwright\|only test runner\|no unit runner" .squad/ARCHITECTURE.md`
  — nenhuma ocorrência.

  `allowImportingTsExtensions` não quebrou o bundler).

## Scope
- In: `biome.json`, `tsconfig.json`, `package.json`, `package-lock.json`,
  `scripts/check-line-cap.sh`, `.gitignore`, `jest.config.ts`, `jest.setup.ts`,
  `.squad/ARCHITECTURE.md`, remoção de `e2e/` e `playwright.config.ts`, e todo arquivo
  em `src/`, `.storybook/`, `.design-sync/`, `next.config.ts`, `prisma.config.ts` que
  precise mudar para o lint passar.
- Out: `.github/` (é a 260812-1108) · a bateria de testes até 90% (é a 260812-1107) ·
  `prisma/schema.prisma` e `prisma/migrations/` · `src/generated/prisma/` ·
  `src/styles/*.scss` e `src/styles/docs/*.mdx`, salvo se uma regra do Biome exigir.

## Forbidden
- Desligar qualquer regra além de `noDefaultExport` e, se comprovadamente
  insatisfazível, `useComponentExportOnlyModules` — e sempre restritas por `includes`
  aos arquivos que o framework obriga. Rebaixar severidade para `"info"`/`"warn"` para
  o `lint` passar é a mesma coisa que desligar e está igualmente proibido.
- Qualquer `// biome-ignore` novo. A correção é o código, não a supressão.
- `continue-on-error`, `|| true`, `--max-diagnostics` ou `--no-errors-on-unmatched` em
  qualquer script.
- Mudar comportamento do app para agradar o linter. Se `noTernary` ou `noJsxLiterals`
  forçarem reescrever uma expressão, o resultado renderizado tem de ser idêntico.
- Introduzir `coverageThreshold` — a barra dos 90% é da 260812-1107.
- Deixar de rodar o `check-line-cap.sh` nos arquivos novos: `jest.config.ts` e
  `jest.setup.ts` estão fora de `src`, mas os dois testes do passo 5 não estão.
