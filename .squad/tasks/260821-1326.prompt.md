# Classificar previsões como fixa ou compromisso

## Outcome

R1. Dado um POST ou PUT em `/api/forecasts`, o sistema persiste `kind` `"fixed"` ou `"commitment"`; um body sem o campo lê `"fixed"`; cada linha já gravada lê `"fixed"` depois da migration.
R2. Dado o modal de adicionar ou editar previsão, o leitor escolhe **Fixa** ou **Compromisso futuro** (radios); o cadastro começa em Fixa; a edição sementeia o valor gravado; o submit envia `kind` junto com `months` e `simulated`.
R3. Dada a lista em `/previsoes`, cada linha mostra um badge **Fixa** ou **Compromisso futuro**, no mesmo `renderPeriod` do badge Simulado.

## Design

- **Contract — `Forecast.kind`.** Prisma `kind String @default("fixed")`. Migration: `ALTER TABLE "Forecast" ADD COLUMN "kind" TEXT NOT NULL DEFAULT 'fixed';` (pasta `prisma/migrations/<date +%Y%m%d%H%M%S>_add_forecast_kind/`). Wire: mesmo envelope `{ data }` / `{ error }`; create e update no Zod.

```ts
// src/lib/forecast-kinds.ts
export const FORECAST_KINDS = ["fixed", "commitment"] as const;
export type ForecastKind = (typeof FORECAST_KINDS)[number];
export const DEFAULT_FORECAST_KIND: ForecastKind = "fixed";
export const KIND_LABELS: Record<ForecastKind, string> = {
  fixed: "Fixa",
  commitment: "Compromisso futuro",
};
```

```ts
kind: z.enum(FORECAST_KINDS).default(DEFAULT_FORECAST_KIND);
```

`Forecast`, `ForecastInput`, `ForecastRow`, `ForecastFormValues` ganham `kind: ForecastKind`. UI: radios, legend **Classificação**, labels de `KIND_LABELS`. Badge da lista: sempre visível, texto de `KIND_LABELS[forecast.kind]`.

- **Contract — PRODUCT.md.** Acrescentar ao bullet **Forecast** em `.squad/PRODUCT.md` (docs em inglês), sem reabrir `simulated`:

  A forecast also has a **kind**: `fixed` (already in the household's rhythm) or `commitment` (a future obligation). Kind is a label for the reader; it does not change the projection. It is orthogonal to **simulated**.

- **Flow** — none: o caminho é o de `simulated` (Zod → service → repo → form → `renderPeriod`).
- **Chose `kind` over `type`** — `type` já é Entrada/Saída.
- **Chose string fechada over boolean** — o pedido é duas categorias nomeadas, não um sim/não.
- **Chose não filtrar o dashboard over um segundo `forecastsFor`** — classificação para o leitor; a projeção não muda.
- **Chose badge sempre visível over só o não-default** — sem isso a Fixa some da lista e só volta no edit.
- **Chose não generalizar TypeToggle** — `kind` não existe em movimentação.

## Steps

1. `FORECAST_KINDS` + frase em `.squad/PRODUCT.md` + coluna Prisma + migration `ADD COLUMN` + entity/repo/Zod default `"fixed"` + testes de schema, kinds e repositório. Rodar `npm run db:setup` para gerar o client. → R1
2. Radios de classificação no `ForecastForm` (cadastro default `fixed`, edit sementeia, submit inclui `kind`). → R2
3. Badge de `KIND_LABELS[kind]` em `renderPeriod`, ao lado do de simulado. → R3

## Forbidden

- Prisma enum, coluna chamada `type`, RedefineTables, editar migration antiga ou `src/generated/prisma/`.
- Filtrar, agrupar ou mudar conta do dashboard por `kind`.
- Checkbox para `kind`, ou um `<select>`.
- Playwright (não existe neste repo).
- Colocar `kind` em `EntryFormBase`.
