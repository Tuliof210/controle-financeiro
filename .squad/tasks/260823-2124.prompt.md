# Responder se dá para gastar e o que mudou

## Outcome

R1. No dashboard `ok`, o leitor informa um valor em reais e recebe uma resposta explícita: cabe no teto do mês corrente (e quanto sobra) ou não cabe (e quanto falta). A conta usa o mesmo `ceiling.monthly` já exibido, no cap ativo — sem endpoint novo.
R2. Depois de criar, editar ou excluir uma previsão ou movimentação com sucesso, a UI mostra o teto do mês corrente antes → depois. Falha ao buscar o teto não reverte o save.
R3. Ao reabrir o dashboard, se teto mensal ou saldo projetado do fim do período mudou desde a última visita a `/` neste browser, uma linha diz o que mudou. Primeira visita: sem essa linha, e a visita grava o snapshot.

## Context

Depende de `260823-2120` e `260823-2121` — o número de referência é o teto da faixa/card, no cap persistido. Não inclui os três modelos Dedicado / Em paralelo / Um de cada vez como peça. Não inclui chips de mês no form de previsão nem o filtro de perfil (P2 da auditoria, fora do recorte).

- **Reuse** `data.ceiling.monthly` e `points.at(-1).cumulative` no payload `ok` (`src/app/api/dashboard/types.ts`). Não há campo novo.
- **Imitate** persistência em `simulation.hook.ts` (effect + try/catch em `localStorage`) para o snapshot da última visita.
- **Reuse** `apiGet` em `src/lib/api.ts` se o fluxo de escrita precisar reler o dashboard depois do save. `EntryScreen` hoje persiste e fecha o modal sem falar de teto.
- **Watch out for** centavos: input do leitor em reais, comparação em cents (mesmo helper de dinheiro do form). Perfil ativo: o snapshot é por perfil (`owner`), senão Família vs uma pessoa mentem. Não bloquear o POST de entrada se o GET do teto falhar. Não usar os três prazos de `GoalRow` como resposta de “posso comprar”.

## Design

- **Contract** — helper puro, sem I/O:

```
canAfford(amountCents: number, ceilingMonthlyCents: number):
  { ok: true, remainingCents: number } | { ok: false, shortfallCents: number }
```

`amountCents <= 0` não afirma “cabe”: o campo vazio/zero não dispara a frase.

Snapshot:

```
KEY = "dashboard-seen"
value = { owner: string, monthlyCents: number, projectedEndCents: number }
```

Diff: linha só se `owner` bate e algum dos dois números mudou.

Delta pós-escrita: imediatamente antes do persist, GET dashboard (`monthly`); depois do persist ok, GET de novo; Notice/role=status na tela de entradas com os dois valores formatados. Sem GET prévio, só o valor depois.

- **Flow** — “posso gastar”: client-only no dashboard. Snapshot: lê no mount de `ok`, compara, depois escreve o valor atual. Delta: na tela que escreveu (`/previsoes` ou `/movimentacoes`), não força `/`.
- **Chose** helper client no teto já carregado **over** `POST /api/afford` — a conta é uma comparação; o payload já está na página.
- **Chose** Notice na tela de escrita **over** redirect ao dashboard — o dono acabou de gravar um lançamento; o delta é o fecho dessa ação.
- **Chose** `localStorage` por owner **over** tabela nova — um operador, um browser, app local.

## Steps

1. Campo + resposta `canAfford` no dashboard `ok`, testes do helper e da UI. → R1
2. Delta do teto após save/delete bem-sucedido em `EntryScreen`. → R2
3. Snapshot da última visita e linha de mudança no próximo `ok`. → R3

## Verify

- R1: `npm test --` nos testes novos do helper `canAfford` e do bloco no `DashboardScreen` — valor abaixo do teto → sobra; acima → falta; vazio → sem frase.
- R2: `npm test -- src/components/EntryScreen/` — após persist mockado ok, a UI contém os dois tetos; GET falho depois do save não chama rollback.
- R3: `npm test -- src/app/_components/DashboardScreen/tests/` — segundo render com monthly diferente mostra a linha; primeiro render não.
- R1–R3: `npm run typecheck` e `npm run lint`.

## Scope

- In: helper puro + UI no dashboard; `EntryScreen` após persist; localStorage do snapshot; testes.
- Out: rota/API nova, modelos de financiamento de objetivo, form de intervalos/kind, filtro de perfil no header, OFX, decoder, `buildCeiling`.

## Forbidden

- Não criar tabela Prisma nem migration.
- Não tornar kind de previsão parte da conta.
- Não usar `variant="hero"` na resposta de “cabe/não cabe”.
- Teto de 100 linhas. Sem dependência nova.
