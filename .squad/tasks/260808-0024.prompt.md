# Adicionar target Meta ao Teto de Gastos

## Outcome
- `/configuracoes` ganha uma seção "Meta mensal" com um único valor em centavos,
  global (família), editável e persistido — sem meta cadastrada, nada quebra.
- O seletor do card Teto de Gastos mostra um 4º segmento **Meta** ao lado de
  25% / 50% / 75%, e ele só aparece quando há meta cadastrada.
- Com Meta selecionada, o teto de cada mês é `min(teto a 100%, meta)`: mês cujo
  100% é 2000 com meta 3000 libera 2000; mês cujo 100% é 3500 libera 3000, e os
  500 restantes seguem para os meses seguintes pelo acumulador que já existe.

## Context
- **Reintroduzir o que foi removido.** `prisma/migrations/20260730120000_drop_settings/`
  derrubou `Settings`, que tinha exatamente `monthlyGoalCents` — "a Meta mensal que
  o dono nunca manteve", sem consumidor. Agora tem um. Volta como singleton
  (`id` fixo, upsert), só com `monthlyGoalCents`; nada de `rangeStart`/`rangeEnd`.
- **Imitar** o recurso Objetivos ponta a ponta: `src/core/entities/goal.entity.ts` →
  `core/repositories/goal.repository.ts` → `infra/repositories/goal.prisma.repository.ts`
  → `app/api/goals/{route,service}.ts` → `configuracoes/_components/SettingsScreen/components/GoalsSection/`.
  O formulário exemplar é `GoalForm/index.tsx` — `<MoneyInput valueCents={...}
  onChange={...} ariaLabel="Valor alvo" />` mais `if (targetCents < 1) setLocalError(...)`
  no `hook.ts`. Aqui não há lista nem CRUD: um campo, um botão Salvar.
- **Reusar** `buildCeiling(points, currentMonth, cap)` em
  `src/app/api/dashboard/ceiling.helper.ts`. A linha do orçamento é hoje
  `const budget = red ? 0 : Math.floor((gap * cap) / 100);`. Meta é o mesmo cálculo
  a 100% limitado pela meta — o teto é `gap`, não o saldo do mês, e o acumulador,
  o `red ? 0`, o piso e os rates `/4` e `/30` continuam valendo sem alteração.
- **Reusar** `src/lib/ceiling-caps.ts`: `CEILING_CAPS = ["25","50","75"]`,
  `DEFAULT_CEILING_CAP = "50"`. O valor viaja como `?cap=`.
- **Cuidado:** `dashboard/route.ts` faz `z.enum(CEILING_CAPS).catch(DEFAULT_CEILING_CAP).transform(Number)`
  — `"meta"` vira `NaN` e contamina todo o payload. E `CapSelector/hook.ts` monta
  `label: \`${cap}%\`` para todo item da tupla, o que daria "meta%".
- **Cuidado:** o valor da meta é lido no servidor (o dashboard já busca dados por
  repositório) — não trafega dinheiro em query param.
- **Cuidado:** `cap=meta` sem meta cadastrada cai em `DEFAULT_CEILING_CAP`, mesma
  doutrina do `.catch` documentada no topo de `dashboard/route.ts`.
- **Cuidado:** `SettingsScreen/index.tsx` tem hoje um `.grid` de duas seções; a
  terceira precisa passar em `e2e/row-overflow.spec.ts`, que roda `/configuracoes`
  em 375, 767, 768, 1024 e 1440px sem overflow horizontal.

## Steps
1. Modelo `Settings` singleton no `prisma/schema.prisma` + nova migration
   (`prisma/migrations/<yyyyMMddHHmmss>_add_spending_goal/`, comentário explicando
   por que a tabela volta), entity, interface de repositório e implementação Prisma
   com upsert. Incluir `Settings` no `db:clean`.
2. `app/api/settings/{route,service}.ts`: GET devolve a meta (ou `null`), PUT faz
   upsert com Zod (`monthlyGoalCents: z.number().int().min(0)`), envelope `ok`/`fail`.
3. Seção "Meta mensal" em `/configuracoes` (pasta de três arquivos), montada no
   `.grid` do `SettingsScreen`, com `MoneyInput` e salvar via `apiPut`.
4. `"meta"` entra em `CEILING_CAPS`; a conversão para número sai do enum e a
   rotulagem do `CapSelector` deixa de assumir porcentagem.
5. Dashboard passa a meta até `buildCeiling`, que aplica `min(teto a 100%, meta)`
   quando o alvo é Meta; sem meta cadastrada, cai no padrão. O payload informa a
   tela se há meta, e o 4º segmento só renderiza nesse caso.
6. Atualizar a cópia de `HINTS.ceiling` em `DashboardScreen/hints.ts` e estender
   `e2e/ceiling-cap.helper.ts` cobrindo Meta: teto do 1º mês ≤ meta e
   `expectScenarios` verde (o piso `ceilingLeft >= 0` mês a mês).

## Scope
- In: `prisma/`, `src/core/`, `src/infra/`, `src/app/api/{settings,dashboard}/`,
  `src/app/configuracoes/`, `src/app/_components/DashboardScreen/`,
  `src/lib/ceiling-caps.ts`, `e2e/`, `package.json` (`db:clean`).
- Out: `pace.helper.ts`, `goals.helper.ts`, seção Objetivos, `Goal` — a meta de
  gastos é outro conceito e não encosta em objetivo de poupança.

## Verify
- `npm run lint` (biome + cap de 100 linhas nos arquivos tocados)
- `npm run build`
- `npm run test:e2e`
- Manual em `npm run dev`: sem meta, o card mostra 3 segmentos; salvando uma meta
  em `/configuracoes`, o 4º aparece e o valor mensal do card fica ≤ a meta.

## Forbidden
- Reviver `rangeStart`/`rangeEnd` no `Settings`, ou permitir mais de uma linha.
- Editar migration já aplicada; a nova é adicionada.
- Trafegar o valor da meta pela query string do dashboard.
- Deixar `transform(Number)` produzir `NaN` para o novo alvo.
- Meta por pessoa, ou mexer nas regras do teto (suffix minimum, acumulador,
  `red ? 0`, floors) além do limite novo.
